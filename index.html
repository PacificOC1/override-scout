About us

We're Team 97230F — Bot Go Brrr — a VEX V5 Robotics team from Highvale Secondary College in Melbourne's south-eastern suburbs, competing in the 2026–27 Override season.

This scouting database was built entirely by our team to track autonomous performance across events — pin counts, AWP rates, robot types, route notation, TrueSkill ratings — and to sharpen our alliance selection at Signature qualifiers and beyond.

All data is updated live throughout the season by our scouting team. The app is free and open to any team that finds it useful.

Scoring Formulas
Complete reference for every formula used across the scouting database — scoring, probability models, skill ratings, and rankings.
Scoring Win Prob AWP TrueSkill RFORCE OPR/DPR OpenSkill
Scoring

Pin Score

pins = goal1_pins + goal2_pins SAWP mode (combined alliance): pins = own_g1 + own_g2 + team_g1 + team_g2

Raw pin count per match entry. Primary leaderboard metric. In SAWP mode all four goal slots across both robots are summed for the alliance total.

Match Score

RawScore = (R1_G1 + R1_G2 + R2_G1 + R2_G2) × 5 AutoBonus = +12 pts → higher-scoring alliance (SC7) = +6 pts → each alliance if raw scores tied FinalScore = RawScore + AutoBonus

Each pin is worth 5 match points. The AutoBonus is awarded to the higher-scoring alliance; on a tie both alliances receive +6 instead of +12.

📐

Worked Example

Red Alliance
R1 → 4 pins total, 0% fail R2 → 3 pins total, 0% fail RawScore = 7 × 5 = 35 pts
Blue Alliance
R1 → 5 pins total, 0% fail R2 → 5 pins total, 0% fail RawScore = 10 × 5 = 50 pts
Blue wins raw (50 > 35) → Blue gets +12 AutoBonus Final: Red = 35 pts Blue = 62 pts With 0% fail rates → P(both succeed) = 100% → Blue win probability = 100%
Win Probability

16-Outcome Model

Each robot independently succeeds or fails. All 2⁴ = 16 combinations are enumerated. For each outcome: P(outcome) = ∏ P(robotᵢ branch) P(succeed) = 1 − FailRate P(fail) = FailRate Scores computed per outcome; bar segments sized proportionally to P(outcome). Red win % = Σ P(outcomes: redScore > blueScore) Blue win% = Σ P(outcomes: blueScore > redScore) Tie % = Σ P(outcomes: scores equal)

Base model. Each robot has a single fail rate that collapses the outcome to 0 pins on failure.

New

Distribution-Aware Model

Extension of the 16-outcome model. Uses each robot's Fail Pin Distribution instead of a single fail → 0-pins outcome. On success: robot scores entered G1 + G2 pins. On fail: robot scores according to its empirical Fail Pin Distribution. All outcome combinations enumerated (cartesian product across all branches). Each branch weight: P(succeed) = 1 − FailRate P(fail, k pins) = FailRate × dist_weight(k) [weights normalised to sum = 1] Red win % = Σ P(outcomes: redScore > blueScore) Blue win% = Σ P(outcomes: blueScore > redScore) Tie % = Σ P(outcomes: scores equal)

Richer model that captures partial scoring on failure. Each partial-pins scenario becomes a separate weighted branch in the outcome tree.

New

Fail Pin Distribution

Input: % weight for each pin count (0 pins, 1 pin, 2 pins, …) Weights normalised to sum = 100%. Example: 0 pins → 60%, 1 pin → 30%, 2 pins → 10% P(fail, 0 pins) = 0.60 × FailRate P(fail, 1 pin) = 0.30 × FailRate P(fail, 2 pins) = 0.10 × FailRate

Discrete empirical distribution entered manually per robot. Models partial scoring when the robot fails its primary objective but still scores some pins.

If no distribution is entered, fail defaults to 0 pins (100%) — the standard 16-outcome model behaviour. Each pin count becomes a separate branch in the outcome tree.

AWP Probability

Autonomous Win Point (AWP)

Earn Conditions (both required)
1. Total alliance pins scored ≥ 7 2. At least 3 goals have ≥ 2 pins each AWP % = Σ P(scenarios where both conditions are met)

AWP is a deterministic rule, not a per-robot probability. For each outcome scenario the calculator checks whether the alliance's combined pin counts satisfy both conditions.

AWP earns Ranking Points (WP) — not autonomous match score. The AWP% shown in the probability legend is the sum of probabilities across all scenarios where the rule is met.

Boolean per entry. AWP Rate = (AWP entries / total entries) × 100%
TrueSkill
New

TrueSkill Win Probability

P(A beats B) = Φ( (μA − μB) / √(2β² + σA² + σB²) ) β = 25/6 ≈ 4.167 (standard TrueSkill β) μ = skill mean σ = uncertainty (standard deviation) Alliance σ pooled: σ_alliance = √((σ₁² + σ₂²) / 2) Φ(x) = standard normal CDF (Abramowitz & Stegun approx.) max error < 1.5 × 10⁻⁷

Source: Microsoft TrueSkill (Herbrich et al., 2006). Data: vrc-data-analysis.com — VRC Worlds 2026 (1,362 teams).

TrueSkill Display Score

ts_score = μ − 3σ μ = skill mean σ = uncertainty Conservative lower-bound estimate. Penalises teams with few matches (high σ). σ shrinks as more matches are recorded.

Also called the ordinal — the 99.7% lower bound on true skill. Loaded from the ts_rankings Supabase table. Higher is better.

RFORCE Rankings

RFORCE Index

Local scouting approximation — not official; no judge awards or full RobotEvents data.
Event Points (EP)
RANK_EP(rank, total) = ((1 + total − rank) / total) × 10 EP = Avg Pins RANK + AWP Rate RANK + Success Rate RANK
Event Rating Factor (RFER)
EventCaliber = avg pins across all teams at that event RFER = 1 + log₁₀(EventCaliber + 1) × EventLevel × EventBonus EventLevel: Local = 1.0 Sig/Reg = 1.25 National = 1.5 World = 2.0 EventBonus = 1 + (n² − 1) / max(1, N²) n = events this team attended N = max events by any team
Final RFORCE Score
EventScore = EP × RFER RFORCE = Σ(EventScores) ÷ events attended
Combined Score
Combined = 60% × normalised(RFORCE) + 40% × normalised(TrueSkill) Both components normalised 0 → 100 before weighting.

Event-weighted performance index. Better performance at higher-caliber events earns a larger RFER multiplier, rewarding teams that compete and win at tough events.

OPR · DPR · CCWM
Experimental

OPR

OPR = avg pins scored per entry Measures raw offensive output per appearance.

Offensive Power Rating. Higher is better.

DPR

DPR = avg of max(0, EventAvg − pins_scored) per entry EventAvg = mean pins across all entries at that event.

Defensive Power Rating. Proxy for how much defensive pressure opponents imposed. Lower DPR = better relative performance under pressure.

CCWM

CCWM = OPR − DPR Positive = adds more than it concedes. Net contribution to winning margin.

Calculated Contribution to Winning Margin. Computed from scouted match entries — each entry is one robot in one match.

OpenSkill
Experimental

Weng-Lin Bradley-Terry Full

Source: Weng & Lin, JMLR 2011 §3.1 — same model as openskill.js v4. Each scouted entry is treated as a 1-v-1 match vs a fixed "field" opponent.

Parameters (openskill.js defaults)
μ₀ = 25 (initial mean) σ₀ = 25/3 ≈ 8.333 (initial uncertainty) β = 25/6 ≈ 4.167 (performance noise) τ = 25/300 ≈ 0.083 (dynamic factor) κ = 0.0001 (σ floor multiplier) Field opponent: μ = 25, σ = σ₀ / 2 Win condition: team pins ≥ event average
Update Equations (Bradley-Terry Full, §3.1)
c = √(σᵢ² + σq² + 2β²) p_iq = Φ((μᵢ − μq) / c) — win probability s = 1 (win) or 0 (loss) Ω = (σᵢ²/c) × (s − p_iq) — mean Δ Δ = (σᵢ²/c²) × p_iq × (1 − p_iq) — var Δ μᵢ' = μᵢ + Ω σᵢ' = √( max(σᵢ²(1−Δ) + τ², (κσ₀)²) ) Ordinal = μ − 3σ (99.7% lower bound) Entries processed: chronological (created_at ↑) Φ(x): Abramowitz & Stegun polynomial max error < 1.5 × 10⁻⁷
⚠️ RFORCE, OPR/DPR/CCWM, and OpenSkill are local scouting approximations computed from manually-entered data and are not official VEX metrics. Accuracy improves with more scouted entries. OPR/CCWM are experimental on sparse datasets.
